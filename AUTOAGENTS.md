# Multi-Agent Autonomous Development System

This document describes how to set up and run a **fully autonomous multi-agent system** that develops the Tallee codebase **without human intervention**. Once bootstrapped, agents run on schedules, coordinate via shared memory, and ship features end-to-end without you needing to open Claude Code, create tasks, or review PRs manually.

**The goal**: You set it up once, then it runs itself. You check in occasionally to steer priorities or read memory/blockers, but the day-to-day development loop (idea → code → review → merge) is 100% autonomous.

## System Overview

The system consists of **6 agents** that mimic a real software team:

| Agent | Model | Role | Frequency | Token Budget |
|-------|-------|------|-----------|---------------|
| **Coordinator** | Haiku | PM/roadmap — prioritizes tasks, prevents conflicts | Every 6 hours | 1000 |
| **Researcher** | Haiku | Proposes features & improvements from web/trends | 2-3x weekly | 1500 |
| **Implementation** | Sonnet | Builds features — writes code, runs tests locally, merges after approval | Every 2 hours | 7000 |
| **Reviewer** | Sonnet | Code quality & adherence checks | Every 4 hours | 2000 |
| **Docs** | Haiku | Updates CLAUDE.md, memory, inline comments | Post-merge | 800 |

## How It Works (The Flow)

```
Researcher discovers idea
    ↓ (writes to backlog.md)
Coordinator prioritizes
    ↓ (creates TaskCreate, marks ready)
Implementation claims task
    ↓ (opens feature branch, writes code)
    (runs: npm run lint, npm run build locally)
    ↓ (opens PR with description)
Reviewer audits PR
    ↓ (approves or requests changes)
Merge to main
    ↓
Docs updates CLAUDE.md & memory
```

## Agent Memory Structure

Agents share state via markdown files in `/memory/`:

```

  MEMORY.md              # Index of all memory files (autogenerated by agents)

```

## Token Optimization Strategies

### 1. Model Allocation
- **Haiku 4.5**: Coordinator, Researcher, Docs (lightweight decision-making, memory management)
- **Sonnet 4.6**: Implementation, Reviewer (coding and code review require better reasoning)
- **No Opus**: Too expensive for your token budget; Sonnet is enough for this codebase scale

### 2. Cache Heavy Context
Store in memory to avoid re-reading on every run:
- `CLAUDE.md` (immutable, ref once per agent startup)
- Recent git log (cache for 24h)
- Code patterns in the repo (update weekly)
- Feature list and priorities (read-write, hourly)

### 3. Scheduled Intervals (Not Continuous)
- **Coordinator**: Every 6 hours (e.g., 8am, 2pm, 8pm)
- **Researcher**: 2-3x weekly (e.g., Monday & Thursday 9am)
- **Implementation**: On-demand when task is claimed
- **Reviewer**: Triggered by PR events (git hooks, if available)
- **Docs**: Post-merge (triggered by git hook or manual)

### 4. Short Feedback Loops
- Use `git diff` + line numbers instead of reading whole files
- Store decisions in memory; don't re-decide
- Link to specific files/lines in comments (e.g., `src/App.tsx:42`)
- Mark tasks as `completed` immediately to signal to other agents

## How to Set Up True Autonomy

**The system is only autonomous if agents run on a schedule without you triggering them.** Set this up once, then forget about it.

### Primary: Use the `schedule` Skill (Remote Triggers)

The `schedule` skill creates **remote agents** that Claude runs on your behalf, on a cron schedule. This is the **canonical way** to achieve autonomy.

```bash
# In Claude Code (one machine), set up these schedules:
/schedule

# Schedule 1: Coordinator
# Name: tallee-coordinator
# Cron: 0 */6 * * *  (every 6 hours: 12am, 6am, 12pm, 6pm)
# Agent: Coordinator (copy prompt below)

# Schedule 2: Researcher
# Name: tallee-researcher  
# Cron: 0 9 * * 0,3  (Monday & Thursday 9am)
# Agent: Researcher (copy prompt below)

# Schedule 3: Implementation
# Name: tallee-implementation
# Cron: 0 */2 * * *  (every 2 hours, check for ready tasks)
# Agent: Implementation (copy prompt below)

# Schedule 4: Reviewer
# Name: tallee-reviewer
# Cron: 0 */4 * * *  (every 4 hours, check for open PRs)
# Agent: Reviewer (copy prompt below)

# Schedule 5: Docs
# Name: tallee-docs
# Cron: 0 12 * * *   (daily at noon, clean up any new docs)
# Agent: Docs (copy prompt below)
```

Once scheduled, these agents run **automatically on your behalf**, without your involvement. You can check progress by reading `memory/agent_status.md` in the repo.

### Fallback: Git Hooks (If Remote Triggers Unavailable)

If you can't use the `schedule` skill, set up git hooks to trigger agents locally:

**`.git/hooks/post-merge`** (runs after merge to main)
```bash
#!/bin/bash
# Trigger Docs agent via remote prompt
# (you'd need a local Claude Code instance running)
```

**`.git/hooks/pre-commit`** (runs before commit)
```bash
# Could validate branch name, lint, etc.
```

But this requires a local machine to stay awake. **Use remote triggers for true autonomy.**

### What NOT to Do
- ❌ Don't manually run agents in Claude Code
- ❌ Don't create tasks by hand
- ❌ Don't open PRs yourself (Implementation does that)
- ❌ Don't merge PRs (Docs handles post-merge cleanup)

**If you do any of the above, you're fighting the autonomy.**

**What NOT to do:**
- Don't implement code. Don't review code.
- Don't merge PRs yourself.
- If stuck on a priority decision: write to `blockers.md`, ask human.

**Remember**: Keep the system moving. If Implementation is idle, make sure there's a task ready.

**Context**:
- Repository: github.com/frikyfriky11/tallee
- Base branch: `agentic` (all feature branches and PRs target this, NOT main)
- Token budget: 1000 tokens per run (stay under this)

### Implementation Agent Prompt

```markdown
You are the Implementation Agent for the Tallee project.

**Your job**: Write code, make PRs, keep the dev loop humming.

**Steps:**
1. Read TaskCreate: is there a `pending` task assigned to you?
   - If yes: claim it (update status to `in_progress`).
   - If no: check if there's a PR you opened that Reviewer has approved — if so, merge it (step 7). Otherwise, wait for Coordinator to create a task.
2. Create a feature branch **from `agentic`**:
   ```bash
   git fetch origin
   git checkout -b feat/[feature-name] origin/agentic
   ```
3. Implement the feature:
   - Edit files per the task description
   - Run `npm run lint` — fix any lint errors
   - Run `npm run build` — verify no type errors
   - Test manually in Chrome at 375x667 viewport using the mcp__claude-in-chrome__* tools
4. Commit with clear message:
   ```
   feat: add [feature name]

   - Implements [what changed]
   - Fixes [task ID if applicable]
   - Testing: [what you tested]
   ```
5. Push: `git push origin feat/[feature-name]`
6. Open PR on GitHub **targeting `agentic`** (not `main`):
   ```bash
   gh pr create --base agentic --title "feat: [feature name]" --body "..."
   ```
   Include: Task ID, what changed, testing notes, link to any related issues.
7. Update `memory/implementation_notes.md` with branch status and next steps.
8. **After Reviewer approves**: merge the PR yourself:
   ```bash
   gh pr merge [PR number] --squash --delete-branch
   ```
   Then mark the task `completed` in TaskCreate and update `implementation_notes.md`.

**What to remember:**
- Always test in browser at mobile size (375x667).
- If blocked: update `memory/blockers.md`, don't go silent.
- Keep commits small and focused.
- Reference CLAUDE.md for architecture decisions.
- Feature branches always start from `agentic`, PRs always target `agentic`.

**Token budget**: 7000 tokens per run (Sonnet, real coding work). If you hit this limit mid-feature, commit what you have and a new run will pick up the task.

**Context**:
- Repository: github.com/frikyfriky11/tallee
- Base branch: `agentic` (never branch from or PR to `main`)
- Local dev: `npm run dev -- --host`
- Check CLAUDE.md before implementing (patterns, file structure)
- All state goes through useGameState hook
- No scrolling on mobile screens (375x667 hard constraint)
```

## What "Autonomous" Actually Means

**Autonomous = agents run on a schedule without you opening Claude Code.**

Once you set up the `schedule` skill (create the remote triggers), here's what happens:

1. **Coordinator runs every 6 hours** — picks next task, creates TaskCreate
2. **Implementation runs (auto-claimed tasks)** — claims the task, codes, opens PR
3. **Reviewer runs every 4 hours** — finds the PR, reviews, approves or requests changes
4. **Researcher runs 2-3x/week** — finds ideas, adds to backlog
5. **Docs runs daily** — cleans up after merges

**You don't touch Claude Code for any of this.** You check progress by:
- Reading `memory/agent_status.md` (agent heartbeat)
- Reading `memory/blockers.md` (if something's stuck, agents ask here)
- Looking at git history: `git log --oneline -10` (what shipped?)
- Reviewing completed PRs on GitHub

**When you want to steer**: Edit `memory/backlog.md` directly with new priorities, or add to `memory/blockers.md` if an agent asked a question. Next scheduled run, agents pick it up.

### Verify Autonomy is Working

Check these signs that the system is truly autonomous:

- [ ] Coordinator has run (check memory/agent_status.md)
- [ ] Implementation has claimed a task and opened a PR
- [ ] Reviewer has left comments on the PR (not waiting for human approval)
- [ ] After merge, Docs has updated CLAUDE.md
- [ ] Next scheduled Coordinator run has picked a new task

If any of these stall, check `memory/blockers.md` — agents left a note.

## Troubleshooting

### Agents Keep Stepping on Each Other
- Problem: Two agents working on same task
- Fix: Coordinator marks tasks `in_progress` immediately after assignment
- Lesson: TaskList is the source of truth for who owns what

### Implementation Gets Stuck
- Solution: Write to `memory/blockers.md`, don't go silent
- Human reads blockers.md at next check-in, unblocks if needed
- Meanwhile, Coordinator picks next task for Implementation

### Reviewer Disappears
- Problem: PRs sit unreviewed
- Fix: Schedule Reviewer more frequently, or
- Trigger Reviewer manually after PR is opened (git hook)

### Token Budget Blows Up
- Problem: Agents are doing too much per run
- Fix: Break work into smaller tasks, stagger agent runs
- Reduce frequency of Researcher (maybe 1x/week instead of 3x)

### Memory Gets Out of Sync
- Problem: Backlog conflicts with git reality
- Fix: Coordinator re-syncs backlog against git log, marks stale items
- Lesson: Memory is a cache; git is the source of truth

## Notes for Future Developers

- **Memory is human-readable**: Check `memory/` before asking an agent why they did something
- **Git history is complete**: `git log --oneline -20` shows what shipped
- **CLAUDE.md is the bible**: Every agent reads it; keep it updated
- **Token budget is real**: If you're adding agents, reduce existing ones or increase frequency intervals
- **Scalability**: With >5 agents, you'll need a stronger Coordinator (maybe Sonnet)

## Hands-Off Mode: Minimal Human Involvement

Once the system is running, your job is **oversight, not operation**. Here's how to stay minimally involved:

### Daily (5 min check-in)
```bash

### Monthly (30 min)
- Audit `memory/decisions.md` — still aligned with your vision?
- Check token usage against subscription (if trending high, reduce Researcher frequency)

- **Edit `memory/backlog.md`** directly: re-prioritize, add new ideas, mark items as `BLOCKED` if they need rethinking

### If You're Handing Off to Another Machine
1. Push all branches to GitHub
2. Copy `memory/` directory to new machine
3. Clone repo on new machine
4. Read AUTOAGENTS.md (this file)
5. Check `memory/blockers.md` for any human decisions needed
6. Run `/schedule` on the new machine to activate agent triggers
7. **You're done** — system is autonomous again
